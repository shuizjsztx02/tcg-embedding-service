# 数据资产现状与归一化方案

生成时间：2026-10-10　数据核对方式：本机实测（TCGPlayer 搜索接口 + 各源公开接口）

---

## 一、结论速览

1. **不存在"以哪一份为准"的单一版本**。四份数据源都是 TCGPlayer 商品目录的下游产物，必须按字段分主：

| 字段 | 权威来源 | 理由 |
|------|----------|------|
| 系列名录、每系列发行量 | TCGPlayer 搜索接口 `aggregations.setName` | 唯一实时、覆盖 47/47 品类；其余三份都是它的快照或子集 |
| 本地库存（我们实际有多少条元数据、多少张图） | `category_cards_final/category_cards/*/products.jsonl` + `images/` | 识别服务真正能用的就是这些 |
| 系列 logo | 外部源（Scryfall / ygoprodeck / TCGdex / Holodex / FAB 官方站 / Bulbapedia） | TCGPlayer 不对外提供系列 logo |

2. **通用主键 = TCGPlayer `setId`**。本地 `products.jsonl` 每个系列只有唯一一个 setId（3279/3279 验证通过）；Holodex 的 set id 实测就是 TCGPlayer 的 setId；Scryfall / ygoprodeck / TCGdex 通过系列名对齐。所有源都能挂到这根主键上，这是收归成一份资产的关键。

3. **缺口**：线上 3643 个系列 / 437,873 张；本地 3279 个系列 / 364,136 张 → **缺 364 个系列、73,737 张卡**。另有 14,699 张（4.0%）本地有元数据但没下载到 200w 图。

4. **补齐可行性**：卡片元数据 100% 可补，现在就能做（已试点验证）；系列 logo 在 8 个目标品线上已做到 1503 / 2039（73.7%），剩余 536 个的堵点逐条见 `doc/seriesToLogo.md` §3.2，多数是该产品本身没有公开的 logo 素材。

## 三、Holodex 与 TCGPlayer 的关系（实测）

**Holodex 不是 TCGPlayer 的官方接口**，是第三方卡牌收藏/扫描 App（getholodex.com，官网自称支持 Pokémon、One Piece、Lorcana、Yu-Gi-Oh!、Magic 共 5 个 + "6 more"）。

但两者**数据同源**，证据：

1. **Holodex 的 set id 就是 TCGPlayer 的 `setId`**。用本地 setId 集合去对 Holodex logo URL 里的数字：
   - Gundam 18/18 (100%)、Riftbound 4/4 (100%)、Star Wars Unlimited 8/8 (100%)
   - Yu-Gi-Oh 143/148 (97%)、Dragon Ball Fusion World 29/30 (97%)、Lorcana 14/15 (93%)
   - Magic 197/216 (91%)、One Piece 20/22 (91%)、Digimon 29/36 (81%)、Union Arena 21/29 (72%)
   - Pokémon 例外：用的是 `base` / `sm13` / `mc3` 这类旧版 set code，不是 setId
2. **系列名就是 TCGPlayer 的 setName 去掉代号前缀**（`SWSH08: Fusion Strike` → `Fusion Strike`）。
3. **但卡牌数量口径不同**：能按 setId 对齐的 487 个系列里，只有 42% 两边数量相同，Holodex 普遍偏大（如 Commander Masters 1975 vs TCGPlayer 1370），推测它把各种变体/印刷都算进去了。**所以 Holodex 的 `cardCountTotal` 不能当发行量用。**

**关于 token**：`crawl/crawl/crawl_sets.py` 里那个 token 解码后是个人登录会话凭证（payload 含用户 UUID、`name: yu li`、`email: yli818141@gmail.com`、`role: USER`），**有效期仅 1 小时**（iat 2026-09-29T10:42 → exp 11:42 UTC）。它不是 API key。

获取方式：登录 getholodex.app → 浏览器 DevTools → Network → 任意发往 `api.getholodex.com` 的请求 → 复制 `authorization: Bearer eyJ...`（1 小时有效，要现抓现用）。

**但换 token 的收益有限**，因为：
- 官网自述支持约 11 个游戏，而 crawl 里已经有 12 个 gameId 的内容，**游戏维度上已经抓全了**；
- 未鉴权探测显示 API 只暴露 `/api/v2/tcg/sets/{gameId}` 和 `/api/v2/tcg/cards/{id}` 两条路由，没有公开的游戏列表接口；
- 缺 logo 的 ~30 个品类（Weiss Schwarz、Cardfight Vanguard、Flesh and Blood、Grand Archive、Shadowverse、WIXOSS、MetaZoo、hololive、CookieRun 等）基本都是现代 TCG 收藏 App 不收录的游戏；
- **现有 logo URL 是公开 CDN**（`holodex-prod-bucket.b-cdn.net`），不需要 token 就能访问，实测抽样 8/8 返回 200。存量数据不会因为 token 过期失效。

token 唯一确定的价值：探明 gameId 13+ 是否存在（现在无法验证）。如果想确认，拿一个 token 来我 1 分钟内探完 gameId 1–60。

## 五、logo 源盘点（实测可用性）

范围限定为 `tcgplayer_sets_rarities_all.json` 的 8 个品线（共 2039 个系列）。

| 源 | 覆盖品线 | 接入方式 | 实得 |
|----|----------|----------|------|
| Scryfall `api.scryfall.com/sets` | 万智牌 | `setCode` ↔ `code`，再按名 | 411（含卡面系列符号 SVG） |
| ygoprodeck `cardsets.php` | 游戏王 | `setCode` ↔ `set_code`，再按名 | 512 |
| TCGdex `v2/en/sets/{id}` | 宝可梦（英） | `setCode` ↔ `abbreviation`，再按名 | 132 |
| Holodex CDN（存量） | 12 个游戏 | 按名（set id 就是 TCGPlayer setId） | 约 120 |
| FAB 官方站 `fabtcg.com` | Flesh and Blood | 按名，抓 sitemap 的 275 个 products/digital-assets 页 | 88 |
| Bulbapedia 图库 + 条目 API | 宝可梦（日） | `setCode` 做图库前缀枚举 + opensearch 找条目 | 177 |
| ONE PIECE 官方站 | One Piece | 产品代号 `ST-27` 之类 | 7 |

**关键结论**：
- **`fabtcg.com` 被 Cloudflare 挡，但用 `curl_cffi(impersonate="chrome")` 可直接绕过**，不需要开浏览器。
- **Bulbapedia 的扩展包 logo 文件名就是 `{系列代码}_{名称}_Logo.png`**，系列代码等于 TCGPlayer 的 setCode，所以能按代码做前缀枚举。很多系列没有 `_Logo` 只有 `_pack` / `_Box` 包装图。
- 反过来，`bulbapedia.bulbagarden.net` / `archives.bulbagarden.net` 的 API **必须用普通 `requests`**，curl_cffi 会吃 Cloudflare 的 403。**同一套代码里不同域名要用不同的 HTTP 客户端。**
- 纯 JS 站点（`pokemon-card.com` 的商品页、官方 YGO 卡牌库）需要 Playwright 渲染才能拿到数据。

**当前覆盖：1503 / 2039（73.7%）**，按可靠性分：系列专属符号/logo 1049、官方包装图/封面 316、继承父系列 123、Scryfall 通用占位图标 15。

**仍无公开源的部分**（536 个系列）：宝可梦日文老扩展包与促销线 278、游戏王铁盒/电子游戏附赠卡等 99、One Piece 早期预组 43、Dragon Ball Super: Masters 非补充包产品 41、宝可梦英文 Trainer Kit/Promo 29、万智牌促销聚合线 24、FAB 的 GEM Pack/Hero Deck 17、Lorcana 新系列 5。逐条原因见 `doc/seriesToLogo.md` §3.2。

**完全找不到公开源的其它品类**：Weiss Schwarz、Cardfight Vanguard、Grand Archive、Shadowverse: Evolve、WIXOSS、MetaZoo、Battle Spirits Saga、Elestrals、hololive OCG、CookieRun、Godzilla、Akora、Kryptik、Sorcery、Alpha Clash 等约 30 个（不在本次 8 个品线范围内）。

## 六、统一数据资产设计

### 6.1 主键

`series_id = TCGPlayer setId`（整数）。跨源对齐规则：

- 本地 `products.jsonl` → 每个 setName 唯一 setId（已验证）
- Holodex → logo URL 里的数字即 setId（Pokémon 除外，需按名对齐）
- Scryfall / ygoprodeck / TCGdex → 按系列名归一化匹配后写入 `aliases`

### 6.2 表结构

**`series` 表**（一行一个系列）

| 字段 | 说明 | 来源 |
|------|------|------|
| `series_id` | TCGPlayer setId，主键 | products.jsonl / 枚举补齐 |
| `line_id` / `line_name` | 品类编号与名称 | 搜索接口 |
| `set_name` | TCGPlayer 原始 setName | 搜索接口 |
| `set_name_norm` | 归一化键（小写去非字母数字） | 计算 |
| `release_date` | 发行日期 | 搜索接口商品字段 |
| `official_card_count` | 该系列发行量 | 搜索接口聚合 |
| `local_card_count` | 本地实际条数 | products.jsonl |
| `local_image_count` | 本地已下载 200w 图张数 | images/ |
| `local_rarity_list` | 本地出现的稀有度集合 | products.jsonl |
| `logo_url` / `logo_source` / `logo_kind` | 系列标识图与出处（holodex/scryfall/ygoprodeck/tcgdex） | 外部源 |
| `logo_verified` | 是否人工核对过 | 人工 |
| `aliases` | 各源写法 `[{source, name, id}]` | 计算 |

**`card` 表**（一行一张卡）：沿用现有 `products.jsonl` 字段，增加外键 `series_id`。

### 6.3 落地步骤

1. **补名录**：用 `script_temp/fetch_all_agg.py` 的聚合结果做 `series` 表骨架（已跑通，47 品类 + DBSC）。
2. **补 setId**：对本地没有的 364 个系列，各枚举 1 张卡的元数据拿 setId。
3. **补明细+图片**：按 setName 分桶枚举（`fetch_cards_search.py` 已有实现），补 73,737 条元数据与缺的图。
4. **挂 logo**：优先 Scryfall（万智牌）、ygoprodeck（游戏王）、TCGdex + pokemontcg（宝可梦），其余沿用 Holodex 存量。
5. **输出**：`series` + `card` 两表落地为单一机读资产，`tcgplayer_sets_rarities_all.json` 与 `doc/seriesToLogo.md` 都从它派生，避免再出现三份数据各说各话。

### 6.4 未决问题

2. 拿不到 logo 的 ~30 个品类，是接受空缺、改用卡面图代替、还是逐个站点自建抓取？
3. Pokémon Japan（455 系列 / 30,379 张）没有任何可用的日文系列标识源，需要单独决策。
