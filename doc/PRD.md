 # 产品需求文档 — TCG 卡牌视觉匹配服务
 
 版本：v1.0
 日期：2026-08-26
 状态：定稿
 
 ---
 
 ## 1. 项目背景
 
 用户拥有约 9434 张宝可梦卡牌的数字扫描图（缩略图，200px 宽），需要构建一个视觉匹配服务。用户拍摄一张真实的宝可梦卡牌照片，系统需返回库中完全一致的卡，或拒绝（如果不在库中）。
 
 预期使用场景：用户日常拍摄卡牌照片，系统自动识别匹配，用于卡牌收藏管理、交易验证等场景。
 
 ---
 
 ## 2. 目标
 
 - **核心目标**：实现一个 API 服务，用户上传真实拍摄的宝可梦卡牌照片，系统返回库中匹配的卡或拒绝
 - **准确率目标**：95%（真实照片测试集上 top-1 命中率 + 拒绝准确率）
 - **并发要求**：当前很低，以跑通为准
 
 ---
 
 ## 3. 用户故事
 
 | ID | 用户故事 | 优先级 |
 |----|---------|--------|
 | US-1 | 作为用户，我拍摄一张库内卡的正面照片，上传后系统能返回这张卡的 ID，以便我确认卡牌身份 | P0 |
 | US-2 | 作为用户，我拍摄一张库外卡（如其他 TCG 卡或非卡物体），上传后系统能拒绝，不会误匹配 | P0 |

 | US-4 | 作为用户，我上传一张卡的照片后，系统能在 1 秒内返回结果 | P1 |
 | US-5 | 作为用户，我知道系统返回结果的置信度，以便决定是否信任匹配结果 | P1 |

 ## 7. 约束与假设
 
 ### 约束
 1. 当前环境 CPU-only，GPU 资源（阿里云）仅在微调阶段使用
 2. 推理阶段保持在 CPU 上运行（ONNX 优化可选）
 3. 输入图片为 JPEG/PNG 格式
 4. 使用 DINOv2 ViT-B/14 作为基线模型
 
 ### 假设
 1. 库内卡图片为 200px 缩略图，可能存在更高分辨率原图
 2. 用户上传的图片已经过前期预处理（裁切、校正），质量较好
 3. 库内卡没有重复 ID（不同卡号的重复 SHA1 已标记）
 4. 不区分卡牌版本（闪卡/反闪/重印视为同一 ID）
 
 ---
 
 ## 8. 风险与缓解
 
 | 风险 | 影响 | 概率 | 缓解措施 |
 |------|------|------|----------|
 | 200px 分辨率上限 | 模型天花板低 | 中 | 寻找高分辨率原图；微调时用 448px 输入 |
 | 无真实照片数据 | 校准不准确 | 高 | 从现在开始收集；先用模拟数据占位 |
 | 重复 SHA1 | 模型无法区分 | 中 | 标记为"无法区分组"，API 返回时提示 |
 | CPU-only 推理慢 | 并发受限 | 低 | 目前并发低，以跑通为准 |
 | 横版图方向误判 | 准确率下降 | 低 | 双方向推理取最高分 |

 ## 9. 术语表
 
 | 术语 | 定义 |
 |------|------|
 | Gallery | 库内卡牌图片集合，用于构建索引 |
 | Query | 用户上传的待匹配图片 |
 | Genuine | 库内卡的真实匹配 |
 | Impostor | 库外卡的非法匹配 |
 | Top-1 准确率 | 检索结果中第一个结果即为正确匹配的比例 |
 | 拒绝准确率 | 库外卡被正确拒绝的比例 |
 | τ (tau) | top-1 分数阈值 |
 | m (margin) | top-1 与 top-2 分差阈值 |
 | Embedding | 图片经过模型后提取的向量表示 |
 | DINOv2 | Meta 自监督视觉 Transformer 模型 |
 | Faiss | Meta 向量检索库 |
 | IndexFlatIP | Faiss 暴力内积索引（等价于余弦相似度，当向量已归一化时） |
 | 单应性矫正 | 将透视变形的四边形通过矩阵变换矫正为矩形 |
 | 对比学习 | 通过正对/负对训练模型，使相似样本的 embedding 靠近，不同样本的远离 |
 | InfoNCE loss | 对比学习中常用的损失函数 |
 | LoRA | 低秩适配，微调大模型时的高效参数更新方法 |
 | Domain gap | 训练数据分布与真实数据分布的差异 |
 | 模拟增强 | 对扫描图施加透视/眩光/模糊等变换，模拟手机拍照效果 |
 | 双方向推理 | 对横版图同时尝试 90° 和 270° 旋转，取最高分方向 |
 | ONNX | 开放神经网络交换格式，用于跨平台推理 |
 | P95 | 95 分位延迟，即 95% 的请求在此时间内完成 |
