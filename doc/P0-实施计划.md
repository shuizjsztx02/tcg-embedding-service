# P0 实施计划：`/v2/recognize` 骨架 + LLM 双模块 + 高/低两档决策 + 评估 harness

> 对应设计文档 §12 P0。基于 Plan agent 的验证结果，修正了 §4.2 方向候选冲突。

---

## 上下文

**目标**：在 `tcg-match-service` 上实现 `/v2/recognize` 端到端管线，满足"客户端预处理 → LLM 品类判断 → DINO 单次 embed → 高/低两档（中置信重排是 P1）→ LLM 兜底 → DB 反查 → 价格"的 P0 闭环。

**设计文档**：`doc/TCG在线识别策略技术方案V2.0.md`（已批准，待修正 §4.2 方向候选冲突）

**前置代码事实**：
- `dino_service.embed(img)` 只做 resize+归一化，无预处理 — 与 §4.0 决策天然契合
- `index_service.products[cat][pid]` 持有完整 product 字典（含价格、customAttributes）
- `index_service.search_visual(cat, feat, top_k)` 返回含 product 的结果
- `index_service.visual_indexes.keys()` = 品类白名单
- LLM 端点：`POST {base}/v1/messages`，Anthropic 风格，base64 图像块
- `script_temp/preprocess.py` 的 `preprocess_query(img)` = 客户端模拟函数（几何标准 504×704）
- 路由注入模式：`_init_route` 挂 service 到 `router.*`，handler 用 `getattr` 取

## 改动清单

### 1. 新增 `app/services/llm_service.py`
- `LLMService` 纯 HTTP 客户端（零模型加载）
- `classify_category(image, whitelist) → {ok, is_card, categories:[{name,confidence}], latency_ms, error}`
- `recognize_card(image) → {ok, identity:{card_name,set_name,card_number,language,card_type,confidence}|None, latency_ms, error}`
- `_to_b64(image, long_edge) → b64` （等比缩放 + JPEG q85）
- `_post(model, blocks, max_tokens) → (text, err)` （超时 + 重试 1 次 + 久经考验的 fence 容忍）
- Prompt 见 Plan agent 报告 §1.1

### 2. 新增 `app/routes/recognize.py`
- `POST /v2/recognize`：`file(必填)` + `ocr_text/ocr_lang/category_hint(可选)`
- **S1**：`category_hint` 在白名单 → 跳过 LLM；否则调 LLM 品类判断 → top-2 候选品类；is_card=false → not_a_card
- **S2**：单次 `dino.embed(img)` → 对 ≤2 候选品类各 `search_visual(top5)` → 合并取最优
  - **修正**：方向候选已由客户端 `preprocess_query` 完成，服务端不做二次方向处理
- **决策**：`score ≥ TAU_HIGH(0.87) AND margin ≥ MARGIN_HIGH(0.02)` → `dino_high`；否则直接 LLM 兜底
- **S3**：LLM 兜底识图 → `_lookup_by_identity` 跨品类 DB 反查（卡号归一化 `_norm_num` 精确匹配 → 系列命中 → 卡名模糊）→ matched/candidates/recognized_no_db
- `decision_path` 全链路日志 + 响应 `scores` 字典
- 工具函数：`_norm_num`（去空白/大写/连字符）、`_assemble_product`、`_assemble_price`（全 `.get()` 容忍缺失字段）、`_merge_visual`、`_lookup_by_identity`

### 3. 修改 `app/models/schemas.py`
- 新增 `RecognizeResponse`：status / decision_path / category / product_id / product / price / candidates / identity / confidence / scores / in_database / warnings / latency_ms

### 4. 修改 `app/config.py`
- 新增：`TAU_HIGH=0.87`、`TAU_LOW=0.75`（P0 不用，预留）、`MARGIN_HIGH=0.02`
- 新增：`LLM_BASE_URL=http://127.0.0.1:15721`、`LLM_CATEGORY_MODEL=qwen3.7-flash`、`LLM_FALLBACK_MODEL=qwen3.7-flash`、`LLM_TIMEOUT_S=8`、`PRICE_AS_OF=""`

### 5. 修改 `app/main.py`
- 新增 import：`LLMService`、`recognize` 路由
- 全局 `llm_service` + startup 注入 `recognize._init_route`
- 模块级注册 `app.include_router(recognize.router)`
- `/v1/*` 零改动

### 6. 修改 `docker-compose.yml` / `.env.example` / `requirements.txt`
- environment 追加 7 个变量（`TAU_HIGH`、`TAU_LOW`、`MARGIN_HIGH`、`LLM_BASE_URL`、`LLM_CATEGORY_MODEL`、`LLM_FALLBACK_MODEL`、`LLM_TIMEOUT_S`）
- `.env.example` 同步追加 + `PRICE_AS_OF`
- `requirements.txt` 追加 `requests>=2.28.0`

### 7. 新增 `script_temp/bench_recognize_v2.py`
- 用法：`python script_temp/bench_recognize_v2.py [--limit N] [--server url] [--category-hint pokemon]`
- 流程：`preprocess.preprocess_query` → 上传 `/v2/recognize` → join `dino-v3-annotations.jsonl` 按 filename
- 只对 `verdict=ok` 行计正样本准确率；`verdict=bad` 行 matched 单独计数为"疑似误采信"
- 输出：总体准确率、分 decision_path 准确率/占比、误采信率、延迟 p50/p95
- 断点续跑 + 进度打印

## 关键边界处理

| 边界 | 处理 |
|------|------|
| LLM 品类超时/失败 | 有合法 hint 用 hint；否则 `status=error, path=category_failed` |
| LLM 兜底超时/失败 | `status=unrecognized, path=unrecognized` |
| `category_hint` 不在白名单 | 忽略、转 LLM、记 warning |
| top-2 品类合并 | embed 只算一次，跨品类 `search_visual` 合并按分取前 5 |
| 卡号格式 | `_norm_num` 归一化相等比对（151/172→151172, XY55→XY55, ST01-011→ST01011） |
| 多匹配 | `status=candidates`，≤ 5 条 |
| 价格字段缺失 | 全 `.get()` 容忍，`medianPrice=null` 透传，部分品类无 `sellers/listings`→null |
| products 记录缺失 | 仍返回 `matched` + `product_id`，`product/price=None` + warning |

## 实施顺序（5 步，可独立验收）

1. **配置管线**：config + .env.example + docker-compose + requirements → 验证 `python -c "from app.config import settings; print(settings.TAU_HIGH)"` 输出 `0.87`
2. **LLMService**：`LLMService().classify_category(img, whitelist)` → 返回 `{ok:True, is_card:True, categories:[...]}`；端点不可达时 `ok:False` 不抛异常
3. **路由 + 接线**：`POST /v2/recognize` 冒烟 → 高分图返 `status=matched, decision_path=dino_high, product_id, product, price`；低分图返 `unrecognized/recognized_no_db/candidates`
4. **评估 harness**：`python script_temp/bench_recognize_v2.py --limit 300` → 产出准确率、分路径指标、误采信率、延迟
5. **回归**：`/v1/health`、`/v1/dino-match`、`/v1/ocr-match` 行为不改前一致
