# DINO 预处理改进与验证（2026-08-31）

本次修改 `/v1/search` 与 `/v1/match` 的图片处理链路，不修改 OCR 链路、图库、模型、索引或拒绝阈值。实际索引为 55,560 个 768 维向量，包含英文与日文卡牌，并非旧项目说明中的 9,434 张。

## 发现与修改

- 旧检测器的最小外接矩形回退会把整幅白图、手与背景判成卡牌。改为检查全部层级轮廓，以及由长边线构成的四角；检查凸性、边长比例、面积与四条边的实际边缘支持度。找不到可靠边界时明确告警，不宣称抠图成功。
- 原四角排序在斜放卡牌的坐标和/差相同时会重复选点。改为围绕中心排序；横卡先调整四角对应关系，再透视变换，避免直接拉伸成竖卡。
- DINO 不再使用上下亮度猜测方向。卡牌裁切尝试 0/180°，原图保留 0/90/180/270° 候选；EXIF 在处理前应用。方向由图库检索选择，不能保证每张照片都能正确判断。
- 保留原有 1% 边缘裁除，减少卡套与透视边缘的背景干扰。原图候选仍在，清晰图库图可以维持原来的输入。
- 检测到偏暗、偏亮、低对比度或细节不足时，为检测到的卡面添加轻度亮度/对比度/锐化候选，同时保留未增强图。无可靠裁切时仅整图多方向检索并提示重拍。没有生成式修复、补字、反光区域填充；饱和高光与丢失细节无法恢复。
- 检测最长边限制为 960px，四角映射回原图。候选最多 8 个，仅保留 168×224 的图像，每批最多 4 个输入模型。12MP 照片原本额外保留约 192 MiB 的四份旋转副本，修复后同一测量新增 RSS 约 8.3 MiB；模型及原始照片本身仍占内存。
- 两个接口共用候选提取、embedding 与排序。不同候选的同一卡牌按最高分合并，第二名也考虑其他方向找到的卡牌，避免漏掉竞争结果而高估 margin。
- 模型输入仍为 RGB、168×224、BICUBIC，ImageNet mean/std、CLS 与 L2 归一化不变；未重建索引。抽查图库原图的向量自相似度约为 1.0。

实现使用现有 OpenCV 与 DINOv2，没有新检测模型或外部图片服务。[OpenCV 轮廓与多边形接口](https://docs.opencv.org/4.13.0/d3/dc0/group__imgproc__shape.html)、[DINOv2 官方实现](https://github.com/facebookresearch/dinov2)。

## 接口与界面

原有响应字段保留；两个 DINO 接口都返回 `warnings` 与 `preprocessing`，后者包含：

- `pipeline: dino-query-v2`、`quad_found`、EXIF 校正后原图坐标系的 `quad`、卡牌面积比。
- 增强前的 `quality`、最终候选的 `selected_quality`，包括模糊指标、饱和高亮占比、亮度与对比度。这些是未正式校准的诊断量，不是准确率或拒绝标准；高亮也可能是卡片上的白色印刷。
- `selected.source`、`selected.rotation_degrees`、候选数与耗时。角度是相对于对应候选图的逆时针旋转，裁切候选已经过透视方向调整，并非原始照片的总旋转角。

搜索页面预览为最终候选的 168×224 JPEG 展示图（归一化前，JPEG 有轻微损失），显示是卡牌裁切、增强卡面还是整图回退，不再笼统声称已完成方向矫正。

## 可复现验证

18 项单元/接口回归覆盖：空白误检、断裂边框、弱对比边框、斜卡四角、横卡透视、EXIF、坐标缩放、质量告警、饱和输入数值安全、候选内存、跨方向分差、去重、空索引与上传异常。API 测试使用真实 FAISS、小型确定性编码器，不启动 OCR/BGE；另以真实 DINOv2 和全量已有向量索引调用两个 API 验证截图案例。

```powershell
python -B -m unittest discover -s script_temp -p 'test_dino_*.py' -v
python -B script_temp/eval_dino_preprocess.py --synthetic 20 --seed 2026 --output-dir script_temp/temp/dino_preprocess/holdout_eval
```

评估工具默认从本地 torch hub 缓存加载 DINOv2；需已有权重、图库和 `pokemon-index`。`--hub-dir` 可指定缓存目录。`--legacy-file` 可指定保存的旧 `preprocess.py`；默认使用未改动的现有 OCR/旧预处理模块。合成测试仅抽样少量图库图片，不读取全库图片；检索使用全部 55,560 个现有向量。

开发集：seed 42，6 张图库卡片 × 8 种条件，共 48 例，Top-1 42→44，Top-5 45→48。

## 限制与下一步验收

**合成测试的 95% 不代表真实拍摄准确率已经达到 95%。** 唯一人工核实的实拍案例是截图区域，现有 `ground_truth.json` 与自动视觉标注存在矛盾，不能作为可靠的整体准确率依据。

上线验收需要人工确认的照片→正确卡牌 ID 清单，同时包含库外卡、非卡牌、严重模糊/反光等负例；需同时统计 Top-1、Top-5、拒绝率与误接受率，再校准 tau/margin。多候选会改变分数分布，旧阈值未获得新的误接受率保证。

照片清单放 `csv/`，字段为 `image_path,card_id`（ID 示例 `704836_200w`，相对路径以仓库为根）：

```powershell
python -B script_temp/eval_dino_preprocess.py --manifest csv/dino_real_manifest.csv --output-dir script_temp/temp/dino_preprocess/real_eval
```

传统边缘检测仍会受手指严重遮挡、复杂背景、多个卡片影响。若真实标注评估显示裁切仍是主要瓶颈，再考虑带真实四角/分割标注的检测模型；本次未引入训练、GPU 或额外 SDK。

当前运行中的 8056 服务没有被停止或重启；代码验证在独立进程中完成。服务重启加载后，可通过响应 `preprocessing.pipeline == "dino-query-v2"` 确认使用新版。保留 OCR 与运行服务，避免在缺少真实验收和完整重启保障时中断使用。
